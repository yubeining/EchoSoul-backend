# 人际关系维度实现方案

## 概述

人际关系维度负责管理角色的社交网络、关系类型、情感连接和互动模式，确保角色在对话中表现出符合其关系背景的社交行为和情感反应。本方案详细描述了如何构建一个全面、动态的人际关系管理系统。

## 14. 数据存储结构设计

### 14.1 主数据库表结构 (PostgreSQL)

#### 14.1.1 关系网络表 (relationship_networks)
```sql
CREATE TABLE relationship_networks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    character_id UUID REFERENCES characters(id),
    target_character_id UUID REFERENCES characters(id),
    relationship_type VARCHAR(50) NOT NULL,
    relationship_level INTEGER CHECK (relationship_level >= 1 AND relationship_level <= 5),
    emotional_intensity DECIMAL(3,2) CHECK (emotional_intensity >= 0 AND emotional_intensity <= 1),
    trust_level DECIMAL(3,2) CHECK (trust_level >= 0 AND trust_level <= 1),
    interaction_frequency VARCHAR(50),
    relationship_status VARCHAR(20) DEFAULT 'active',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 14.1.2 情感连接表 (emotional_connections)
```sql
CREATE TABLE emotional_connections (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    relationship_id UUID REFERENCES relationship_networks(id),
    emotion_type VARCHAR(50) NOT NULL,
    emotion_intensity DECIMAL(3,2) CHECK (emotion_intensity >= 0 AND emotion_intensity <= 1),
    emotion_stability DECIMAL(3,2) CHECK (emotion_stability >= 0 AND emotion_stability <= 1),
    expression_style VARCHAR(50),
    trigger_events JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 15. 数据访问接口

### 15.1 RESTful API设计
- **GET /api/characters/{id}/relationships** - 获取角色关系网络
- **GET /api/characters/{id}/emotional-connections** - 获取情感连接
- **POST /api/characters/{id}/relationships** - 创建关系
- **PUT /api/characters/{id}/relationships/{rel_id}** - 更新关系

### 15.2 GraphQL接口设计
```graphql

  id: ID!
  relationships: [Relationship]
  emotionalConnections: [EmotionalConnection]
}

```
